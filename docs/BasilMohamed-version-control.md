## Topic: Version Control & Git

Version control, also known as revision control, records changes to a file or set of files over time so that you can recall specific versions later. In this class, we are learning Git. Update the information below where indicated.

**1. There are three types of version control.**

1. **Local Version Control**: Keeps revisions of files locally on a single computer, typically using a simple database system to manage the changes over time.
2. **Centralized Version Control (CVCS)**: Uses a single central server containing all versioned files. Clients check out files from that central place (e.g., Subversion/SVN).
3. **Distributed Version Control (DVCS)**: Clients fully mirror the entire repository locally, including its full history. If a server dies, any client's repository can be copied back up to restore it (e.g., Git).

**4. Using .gitignore and Why it's Important**  
Most repositories contain a .gitignore file.

- What is the purpose of this file?
  <br>
  The purpose of this file is to tell Git exactly which files and folders to intentionally ignore. This ensures that things like system files, build artifacts, or sensitive information (like passwords or API keys) are not accidentally tracked or uploaded to the public repository.

- What is the "**.DS_Store**" file and why would you want to ignore it?
  <br>
  A `.DS_Store` file is a hidden file automatically generated by the macOS operating system to store folder-specific viewing preferences (like icon positions). You want to ignore it because it is completely irrelevant to the source code and only clutters the repository with useless OS-specific files.

- What other file or folder would you want to add to a .gitignore file and why?
  <br>
  I would add IDE configuration folders (like `.vs/` for Visual Studio). These folders contain personal window layouts and local settings that are specific to my machine, and they shouldn't be shared with other developers or pushed to the repository.
